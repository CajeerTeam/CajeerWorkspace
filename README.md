# CajeerWorkspace · PHP 1.6.1

Веб-приложение для команды, которая ведёт собственные, клиентские и open-source проекты. Владелец создаёт проект, тимлид назначает задачу, разработчик отмечает результат. Бухгалтер проводит поступление или расход, юрист загружает договор и его редакции. Каждая из этих операций сохраняется в SQLite или PostgreSQL.

## Запуск

Для стандартной установки SQLite нужен 64-разрядный PHP 8.3–8.x с CLI, PDO и драйвером PDO SQLite (SQLite 3.27+), cURL с HTTPS, session и OpenSSL. Для PostgreSQL 14+ вместо PDO SQLite нужен pdo_pgsql и настройка подключения (см. [ORGANIZATIONS.md](docs/ORGANIZATIONS.md)). ext-ctype не требуется: числовые строки проверяются независимо от локали. CLI и FPM должны удовлетворять одним требованиям; `doctor` должен вернуть код 0 перед `init`. Для первой установки достаточно PHP. Composer, Node.js и внешние аккаунты не требуются. Из каталога, в который распакован ZIP, выполните команды ниже.

```sh
cd CajeerWorkspace
php bin/workspace doctor
php bin/workspace init owner@example.org "Владелец"
php -S 127.0.0.1:8080 -t public
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080) и войдите с почтой и паролем, введёнными при установке. Замените пример почты своим адресом. В интерактивном Unix-терминале CLI скрывает ввод пароля. При автоматизации передавайте пароль через стандартный ввод. Пароль занимает 12–72 байта. Данные появятся в `var/`. Повторный `init` сообщает о существующем владельце.

## Обновление с 0.1.0 / 0.1.1 / 0.1.2 / 0.2.0

Остановите HTTP/FPM, cron и CLI; отдельно сохраните старый код и конфигурацию. На новом коде выполните `php bin/workspace doctor`, `php bin/workspace migrations` и `php bin/workspace upgrade`. Перед изменением схемы создаётся проверенный снимок SQLite с SHA-256. Можно передать абсолютный путь новой копии; без аргумента копия сохраняется в каталоге данных. Все миграции и их журнал фиксируются атомарно. Повтор команды безопасен, веб-запросы не обновляют схему. Полная процедура, проверка и возврат: [UPGRADE.md](docs/UPGRADE.md).

Полный дистрибутив собирается `python3 tools/release.py build` и проверяется `python3 tools/release.py verify dist/CajeerWorkspace-1.6.1.zip`. Сборка формирует внутренний SHA256SUMS и отдельную SHA-256 сумму ZIP. Python не требуется для веб-приложения; локальный исполнитель деплоя требует Python 3.9+ на Linux.

## Первый проект

1. В разделе **Проекты** создайте проект, выберите тип и при необходимости укажите заказчика.
2. Добавьте участника приглашением или командой ниже (только первая организация). В карточке проекта откройте ему доступ, создайте задачу и назначьте исполнителя. Разработчик увидит её в своей очереди и сможет изменить статус.
3. Перейдите в **Финансы проекта**, проведите поступление и расход. Задайте период, проверьте движение отдельно для каждой валюты и скачайте CSV этой выборки. Ошибочную запись можно сторнировать. История сохраняет исходную операцию и её коррекцию.
4. В **Документах проекта** загрузите PDF до 2 МиБ. Откройте карточку, добавьте следующую версию и скачайте обе по отдельности. У каждой редакции есть время, автор и SHA-256.
5. Привяжите к проекту нужные сервисы. После настройки и опроса в карточке появится их состояние.

```sh
php bin/workspace user:add dev@example.org "Разработчик" developer
php bin/workspace user:add finance@example.org "Бухгалтер" accountant
php bin/workspace user:add legal@example.org "Юрист" legal
```

Смена пароля и блокировка отзывают текущие веб-сессии. Сессия действует до 12 часов и завершается после 30 минут бездействия. Временные метки и текущая дата кассовой книги используют UTC.


## Подключения

Начальная конфигурация пуста. Чтобы сразу опросить пример открытого GitHub-репозитория, выполните команды ниже. Остальные адреса в примере пусты. Полная таблица маршрутов, секреты, cron и примеры отдельных экземпляров описаны в [руководстве по подключениям](docs/INTEGRATIONS.md).

```sh
cp config/connections.example.json config/connections.local.json
php bin/workspace sync github
php bin/workspace profile
php bin/workspace protocol github
```

В разделе **Подключения** доступны профиль стенда, ответственные, интерфейсы, API, наблюдаемые версии, последние успешные проверки и отдельный протокол каждого экземпляра. `profile --check` проверяет заполненность и свежесть результатов девяти типов, но не заменяет приёмку реальных инсталляций. Версия, которую API не сообщает, не выдумывается: оператор может указать проверенную установленную версию отдельно. Подробнее в [руководстве](docs/INTEGRATIONS.md).

## Бухгалтерия и документы

Кассовая книга фиксирует факт движения денег по проекту. Суммы хранятся целыми числами в сотых долях RUB, EUR, USD, PLN или GBP. Введение новой валюты требует явной настройки точности. В итогах выбранного периода сторно уменьшает сумму исходного типа на дату корректировки. CSV содержит все строки выборки, включая корректировки. Полный план счетов, двойная запись и сверка банковских выписок относятся к 0.5.x.

Реестр хранит версии исходных PDF внутри БД. Проверка маркеров PDF ограничивает формат загрузки. Электронную подпись, полномочия подписанта и юридическую действительность файла стартовый выпуск не устанавливает. Этапы согласования, шаблонов по юрисдикциям и интеграции с провайдерами подписи описаны в [дорожной карте](ROADMAP.md).

## Установка под aaPanel / PHP-FPM

Разместите репозиторий, например, в `/www/wwwroot/cajeer-workspace`. В настройках сайта aaPanel укажите рабочий каталог `/public` и PHP-FPM поддерживаемой версии. Для Nginx или Apache документ-корнем служит только полная директория `.../CajeerWorkspace/public` (либо эквивалентный путь вашей установки). Точка входа — `index.php`. Маршруты вида `/?p=projects` работают без rewrite. Включите HTTPS и заголовок HSTS в настройках своего сайта после проверки домена.

CLI и FPM должны читать общие настройки и иметь запись в каталог данных. Запускайте команды от системного пользователя этой установки. PHP должен читать `app/`, `views/`, `database/` и конфигурацию за пределами docroot. При использовании open_basedir разрешите корень приложения и выбранные каталоги данных и временных загрузок. Для PDF установите `upload_max_filesize=2M` или больше, `post_max_size=4M` или больше, аналогичный лимит на прокси. `display_errors=Off` подходит для опубликованной установки. Встроенный веб-сервер PHP предусмотрен для локального запуска.

| Параметр | Назначение |
| --- | --- |
| `WORKSPACE_DATA` | Абсолютный путь к защищённому каталогу SQLite, сессий и блокировки опроса. По умолчанию `var/` в корне репозитория. |
| `WORKSPACE_DB` | `sqlite` (по умолчанию) или `pgsql`; PostgreSQL требует PGHOST, PGPORT, PGDATABASE, PGUSER и защищённой настройки аутентификации. |
| `WORKSPACE_CONFIG` | Абсолютный путь к JSON подключений. По умолчанию `config/connections.local.json`. |
| `WORKSPACE_HTTPS=1` | Для TLS на доверенном обратном прокси принудительно выставляет Secure cookie. Передайте настройку в FPM, а внутренний HTTP-порт ограничьте прокси. |
| `WORKSPACE_GITHUB_TOKEN`, `WORKSPACE_AAPANEL_KEY` | Ключи опциональных интеграций в окружении пользователя, который выполняет `sync`. |

`GET /health.php` проверяет доступ к выбранной базе, версию схемы и наличие активного владельца. Возвращает HTTP 200 с `ready` или 503 с `unavailable`. Готовность внешних сервисов выводится отдельно на странице подключений.

## Резервная копия и восстановление

Ниже — процедура SQLite. Для PostgreSQL используйте `pg_dump` и `pg_restore`, см. [ORGANIZATIONS.md](docs/ORGANIZATIONS.md).

```sh
php bin/workspace backup /srv/cajeer-backups/workspace-001.sqlite
```

Каталог назначения должен существовать, поддерживать жёсткие ссылки и находиться вне docroot. Команда создаёт согласованный снимок SQLite через `VACUUM INTO`, проверяет целостность и внешние ключи, затем публикует копию под новым именем. В копию входят пользователи, хеши паролей, проекты, операции и все PDF. Храните её с ограниченным доступом. Секреты подключений и JSON-конфигурацию резервируйте отдельно.

Для восстановления остановите FPM этой установки и задание опроса. Создайте **новый пустой каталог данных**, положите туда снимок как `workspace.sqlite`, назначьте права сервисному пользователю и переключите `WORKSPACE_DATA` для FPM и CLI. Запустите приложение, проверьте `/health.php`, вход и скачивание известной редакции PDF по SHA-256. Возобновите cron. Отдельный каталог исключает повторное использование старых файлов WAL и сессий. Исходный каталог сохраняется для обратного переключения.

## Проверки

```sh
php tests/integration_profiles.php
php tests/run.php
php tests/migrations.php
python3 tests/release.py
python3 tests/web_e2e.py
python3 tests/tenant_schema.py
```

Второй сценарий требует Python 3.9+, OpenSSL CLI и свободные порты loopback. Для альтернативного PHP задайте `PHP_BIN`. Проверки создают временные установки, запускают HTTP-сервер, проверяют реальные формы и загрузки, права разных ролей, HTTPS-фикстуры семи Cajeer-продуктов и aaPanel, копирование и восстановление. PHP-тест отдельно проверяет запрос GitHub и отбор сохраняемых полей. Файл GitHub Actions задаёт матрицу PHP 8.3, 8.4 и 8.5.

Для 0.1.1 добавлены проверки профиля, версий, миграции, отказа и восстановления, ротации ключа aaPanel, истории и прав. Локальные HTTPS-ответчики не являются реальными инсталляциями продуктов. Приёмку живого стенда оператор проводит по инструкции в `docs/INTEGRATIONS.md`.

Новые проекты закрыты для остальных участников, владельцы ограничены выбранной организацией. При переходе существующие данные и прежние права перенесены в первую организацию. Веб-раздел «Команда» управляет группами и приглашениями, переключатель организации доступен в боковой панели. Для PostgreSQL 14+ и переноса данных из SQLite см. [Руководство по полномочиям и двойному контролю](docs/PERMISSIONS.md): проектные роли, заявки, согласование, сторно, отзыв доступа, аудит и обновление схемы 5 для SQLite/PostgreSQL.

## SkiF4er ID, MFA и клиентский кабинет (0.2.2)

[Настройка и эксплуатация авторизации](docs/AUTHENTICATION.md): серверный OIDC Authorization Code + PKCE, явная привязка `iss + sub`, refresh/introspection, Back-Channel Logout, TOTP для чувствительных действий и отдельный гостевой кабинет. Схема 6 сохраняет бизнес-данные и прежние PDF. До настройки OIDC доступен локальный режим. Для чувствительных действий в любом режиме задайте `WORKSPACE_MFA_KEY` и подключите TOTP в разделе «Безопасность». В OIDC-режиме локальный пароль доступен только явно назначенному аварийному владельцу с TOTP и включённым флагом.

## Планирование проектов (0.3.0)

В карточке проекта — вехи со сроком и прогрессом, доска из трёх статусов, backlog незавершённых задач, приоритеты, комбинированные фильтры. Карточка задачи содержит заказчика результата, многострочные критерии приёмки, исполнителя, срок, веху и направленные зависимости. Менеджер или владелец редактирует план; назначенный исполнитель меняет статус. Незавершённые зависимости блокируют начало и завершение; циклы отклоняются. Закрытие вехи требует хотя бы одной задачи и завершения всех связанных задач с заполненными условиями приёмки. Устаревшие изменения отклоняются; операции аудируются. Миграция 007 оставляет незаполненные условия старых задач, сохраняет исходные статусы, ID, финансовые записи и PDF. Подробнее: [PLANNING.md](docs/PLANNING.md).

## Спринты, загрузка и учёт времени (0.3.1)

В проекте доступен раздел «Спринты, загрузка и таймшиты»: спринты с оценками задач и фиксацией завершённости, недельная доступность участников, ввод фактических минут, отправка, согласование и возврат таймшитов. Ставка фиксируется при отправке; почасовые суммы считаются в целых минорных единицах, фиксированная цена проекта не умножается на часы. Согласованные часы неизменяемы, повторный запрос не удваивает время; финансовые данные защищены проектными правами и MFA. См. [WORKLOAD.md](docs/WORKLOAD.md).

## Клиенты и заказы (0.3.2)

Справочник контрагентов и контактов, запросы клиентов, версионированные предложения, сметы по этапам, задачи, сдача и приёмка через изолированный кабинет SkiF4er ID. При приёмке сохраняются согласованная цена, объём, подтверждённые минуты и решение клиента. См. [CLIENTS.md](docs/CLIENTS.md).

## Open-source workflow (0.3.3)

Для проекта типа OSS владелец или менеджер настраивает публичный профиль, публикует вехи, выдаёт одноразовые приглашения contributor, обрабатывает issue/PR, связывает вклад с задачей и публикует неизменяемые release notes. ## Additional Auth (1.1.0)

В смешанном режиме обычный пароль и связанный SkiF4er ID ведут в одну запись. Владелец организации после входа через ID и свежего TOTP может потребовать ID для своей организации в разделе «Команда».
