# AI Assistant · 1.3.0

Ассистент встроен в Workspace. Это независимый запрос OpenAI Responses API, а не подписка ChatGPT, не внешний чат и не агент с доступом к инфраструктуре. По умолчанию функция выключена. При отключении или отказе OpenAI остальные модули работают штатно.

## Настройка

Владелец установки согласует передачу ограниченных данных конкретных проектов в OpenAI; владелец проекта проверяет содержимое названий задач, вех и выпусков. Не включайте проекты, где эти поля содержат секреты или данные, которые нельзя передавать поставщику. Храните ключ в защищённом окружении PHP-FPM, а не в репозитории, URL, браузере или общей конфигурации интеграций.

```ini
WORKSPACE_AI_ENABLED=1
WORKSPACE_AI_PROJECT_IDS=12,34
WORKSPACE_OPENAI_MODEL=gpt-4.1-mini
WORKSPACE_OPENAI_API_KEY=<secret-from-OpenAI-API-project>
```

ID и модель — пример; укажите реальные пилотные ID и доступную в вашем API-проекте модель с поддержкой Responses API и Structured Outputs. Перезапустите FPM после настройки. Отдельно настройте бюджет и ограничения API-проекта. Ключ не нужен GitHub-издателю или процессу обновлений. Разрешите исходящий HTTPS к `api.openai.com` с доверенным CA. Прокси и redirects отключены намеренно. Для выключения установите `WORKSPACE_AI_ENABLED=0` и перезапустите FPM. Функция не требует изменения схемы 36.

## Использование

В меню «AI-ассистент» или из проекта выберите один разрешённый проект, тему, необязательные ключевые слова (до 120 символов), вопрос (до 1200 символов), подтвердите передачу данных и отправьте форму. Например, тема «Обзор и препятствия к выпуску», без ключевых слов, вопрос «Что мешает выпустить этот проект?». Для конкретного объекта укажите часть названия или тег в поле поиска; поиск буквальный, не семантический. Ответ — один запрос; последующий вопрос не использует предыдущий ответ. Ссылки `[T…]`, `[M…]`, `[R…]` строятся из разрешённых строк БД на сервере. Текст ответа экранируется и не превращается в HTML или Markdown; ответы с URL/ссылочным синтаксисом модели либо неизвестными ссылочными ID отклоняются. Повторный GET не показывает старый ответ.

- Задачи: существующая доска/поиск, состояние, приоритет, срок, версия, признак незавершённых зависимостей и ID вехи. Без поиска максимум 8 todo, 8 doing и 4 done. С поиском максимум 20 совпадений; поля результата и критериев могут участвовать в локальном поиске, но сами не отправляются.
- Вехи: существующий доменный подсчёт задач и завершённых задач, состояние, срок, версия. До 20 строк, ограничение указано в ответе.
- Релизы: право `connections` обязательно, как в существующей карточке релиза. До 20 карточек, тег, SHA, состояние, время и версия, последнее доменное сообщение об ошибке проверки (при активной привязке), исторический результат CI с временем проверки и количеством проверок. Наблюдение старше 15 минут отмечается как устаревшее. Состояние `historical_success` не означает зелёный CI сейчас: никакого онлайн-чтения GitHub нет; отсутствие наблюдения помечается `unknown`. При отключении/смене привязки скрывается прежнее доказательство CI. Changelog, полное evidence, артефакты и данные репозитория не отправляются.

Только текущая организация и проект: `allowedProject`, `projectRole`, `discoverySearch`, `planningRows`, `planningTask`, `planningMilestones`, `releaseRow`/`releaseRepo`. Приглашённые клиенты и contributor не имеют доступа к ассистенту. Нет инструментов, команд, SQL от модели, поиска по всем проектам, документов, финансов, сырых логов, токенов, имён/почты пользователей или файлов. Названия объектов и вопросы являются произвольным текстом: оператор должен соблюдать политику данных. Текст внешнего объекта не считается инструкцией. Модель может ошибаться; отсутствие строки в ограниченной выборке не доказывает отсутствие проблемы.

Перед отправкой и после ответа проверяются сессия/организация, права и разрешённые поля; если наблюдаемый контекст изменился, результат отбрасывается. Отзыв доступа не может отменить данные, которые уже были переданы провайдеру в момент действующего доступа. Нет хранения истории в БД, сессии, файле или через `previous_response_id`; `store:false` для Responses API. Это не гарантия Zero Data Retention: правила хранения/служебных журналов выбранного API-проекта и договора проверяет оператор. См. https://developers.openai.com/api/docs/guides/your-data и https://developers.openai.com/api/reference/resources/responses/methods/create.

Ограничения: максимум 60 объектов на запрос, 64 KiB входного JSON, 1800 выходных токенов, 256 KiB ответа, 35 секунд на HTTP, 8 запросов на сотрудника и 40 на установку за окно существующего ограничителя (10 минут). При пустой выборке вызова API нет. 429, таймаут, отказ, неполный или неверный ответ отображаются как ошибка без раскрытия тела ответа или ключа. Автоматического retry нет. Используются только существующие записи ограничения частоты и штатное обновление сессии; записи проекта не меняются.

## Приёмка

```bash
php tests/assistant_unit.php
php tests/assistant_db.php
# В CI с выделенной PostgreSQL:
php tests/assistant_db.php --postgres
```

На стенде выполнить живой запрос с тестовым API-ключом и выбранной моделью. Проверить задачи, вехи и релиз, ссылку на факт и отсутствие утверждения о текущем CI без наблюдения. Два пользователя разных организаций, приватный клиентский проект, пользователь без connections: проверить выбор проекта и прямой POST с чужим ID. Во время запроса отозвать членство или право, проверить отсутствие ответа/ссылок. Проверить выключенный AI, неверный ключ, 429/таймаут, вредоносный текст задачи, невозможность выполнить запись. Проверить что вопрос/ответ отсутствуют в обычных логах (не настраивать запись тела запроса на прокси) и БД. Зафиксировать модель, время, версию, результаты и обезличенные доказательства. Тестовые ответы API в CI не являются живой приёмкой. Для `assistant_readonly` в Production Release Gate требуется фактический протокол этих проверок.
