# AI Assistant · 1.3.2

Встроенный ассистент Workspace использует OpenAI Responses API. Не является подпиской ChatGPT. Обычные вопросы — только чтение одного проекта. Модель не имеет инструментов записи, SQL, shell или внешних действий. Подтверждаемые черновики используют отдельные серверные операции. По умолчанию выключен.

## Настройка установки

В защищённом окружении FPM и CLI (значения ID и моделей — примеры):

```ini
WORKSPACE_AI_ENABLED=1
WORKSPACE_AI_PROJECT_IDS=12,34
WORKSPACE_OPENAI_MODEL=gpt-4.1-mini
WORKSPACE_AI_MODELS=gpt-4.1
WORKSPACE_OPENAI_API_KEY=<secret>
```

Дополнительные модели перечисляются через запятую без пробелов. Оператор выбирает проекты и разрешённые модели с Responses API и Structured Outputs; владелец организации не может расширить список. Ключ не передаётся браузеру и не нужен издателю релизов. Разрешить HTTPS к api.openai.com с проверкой CA, без прокси/redirect. Настроить лимиты расходов API-проекта отдельно. Перед передачей данных проверить правовые основания и содержимое полей. `store:false` не исключает служебное хранение поставщиком; правила OpenAI и договор обработки данных проверяются отдельно. Отключение `WORKSPACE_AI_ENABLED=0` и перезапуск FPM не отключают прочие модули.

## Политика организации

Владелец на странице «AI-ассистент» с актуальным MFA выбирает разрешённые типы, модель из списка оператора, 0–1000 запросов за сутки UTC и 0–30 суток хранения ответов. При миграции по умолчанию доступны только задачи, вехи, релизы, модель установки, 40 запросов/сутки, история выключена. Ноль запросов запрещает обращения к API. Квота общая для организации, расходуется атомарно до отправки, включая неудачные вызовы; пустая выборка не расходует её. Дополнительно остаются лимиты 8 запросов пользователя и 40 установки за 10 минут. Это лимит запросов, не токенов или денежных расходов. Смена политики журналируется и удаляет прежние ответы; конфликты версий формы отклоняются.

## Контекст

Выбрать проект и тему «Контекст по роли» либо разрешённую конкретную тему. Никаких новых привилегий: используются существующие роли и гранты проекта.

| Роль | Контекст |
| --- | --- |
| Владелец | Бюджет текущего месяца: план, факт, отклонение, маржа по валютам, неизвестные затраты и часы без тарифа. Только валюты с утверждённым в системе бюджетом. |
| Менеджер (тимлид) | Незавершённые задачи с блокирующими зависимостями. |
| Владелец клиентского проекта (фрилансер) | Этапы, предложения draft/offered/accepted и результаты, ещё не принятые клиентом. |
| Бухгалтер / finance_reader | Просроченные неоплаченные счета; при наличии полномочий бухгалтерского журнала — расхождения банковских операций, все распределения которых относятся к выбранному проекту. Нераспределённые общие операции не передаются. |
| Юрист / legal_reader | Сравнение двух последних редакций договора: даты, валюта и признаки изменений суммы, реквизитов, полномочий, документа и приложений. Без извлечения текста PDF или приватных условий. |

Чувствительные темы требуют свежего MFA (5 минут) и явного разрешения в политике. Фрилансер/тимлид не новые RBAC-роли. Если ролевая тема запрещена, отображается разрешённый общий обзор. Ключевые слова применяются к задачам, вехам и релизам; для чувствительных тем используется ограниченная доменная выборка. Для каждой темы максимум 20 источников; банковский контекст — максимум пять выписок; сравнение договоров — выборка последних 50 карточек. Не является полным финансовым или юридическим аудитом. Общий обзор максимум 60 объектов. В запросе не более 64 КиБ, ответ до 1800 токенов, HTTP timeout 35 секунд.

Ссылки формируются сервером из разрешённых объектов, текст экранируется, неизвестные ссылки и URL модели отклоняются. Денежные значения для бюджета и расхождений выводятся из доменных расчётов, а не вычисляются моделью; числовые утверждения модели вне ссылочных ID для этих тем отклоняются. Проверять выводы, модель может ошибаться. Не передаются исходные PDF, контакты, приватные условия, сырые журналы, ключи или токены. Сохранённое CI-наблюдение не означает живой статус GitHub. Вопрос и ключевые слова вводятся пользователем — не вводить секреты или персональные данные.

## Хранение

История личная, отдельно по организации, сотруднику и проекту; не используется как контекст последующих вопросов. При сроке больше нуля сохраняется ответ, идентификаторы источников, тема, поисковые слова, отпечаток контекста и время; вопрос и сырой ответ API не сохраняются. До показа повторно проверяются права, политика, MFA и отпечаток актуальных объектов; изменившийся контекст скрывает старый ответ. Показывается до 20 ответов. Просроченные строки удаляет `php bin/workspace ai:purge`, также штатный `reliability:work` и чтение истории. Настройте cron/worker не реже раза в сутки даже при отключении AI. Резервные копии имеют отдельную политику хранения; удаление из рабочей БД не удаляет их автоматически. Счётчики квоты хранятся отдельно, старые дни удаляются при новых запросах.

## Приёмка

Выполнить `php tests/assistant_unit.php`, `php tests/assistant_db.php` и PostgreSQL-ветку CI. На реальном пилоте проверить две организации, закрытый клиентский проект, все пять контекстов, ограничения бюджета по валютам, MFA, запрет передачи приватных полей, отзыв прав во время запроса, смену политики, параллельную квоту, неудачный запрос, удаление по TTL и отключение AI. Подтвердить точные суммы по экрану экономики/счёта/банка и признаки изменений по карточке договора. Проверить реальные ответы модели и ссылки, отсутствие записи в бизнес-объекты; измерить качество на обезличенных примерах. Положительные доказательства включить в `assistant_readonly` и `assistant_role_policy` регламента PRODUCTION.md. Локальные тесты с имитацией API не заменяют реальный пилот.


## Подтверждаемые черновики (1.3.2)

На странице AI выбранного проекта с актуальным MFA откройте нужный тип черновика, укажите задачу для модели и подтвердите передачу ограниченного контекста. Предпросмотр показывает точные поля, получателя или назначение, исходный объект, текущие/предлагаемые значения и ссылки на разрешённые источники. Модель не определяет адресата, идентификаторы операций, цену, сроки или права. Не вводите секреты, адреса и персональные данные в задание. Для просмотра и подтверждения требуется актуальный MFA (5 минут), в том числе повторный после истечения.

| Тип | Права и политика | Результат подтверждения |
| --- | --- | --- |
| Задача | manage, задачи | Создание через `createTask`; исполнитель, срок и приоритет выбираются пользователем, заказчик результата — название проекта; веха не назначена. |
| Отчёт | разрешённые задачи/вехи/релизы | TXT со сводкой доступной выборки и источниками; личная выгрузка. |
| Release notes | manage + connections, релизы | TXT для выбранной карточки и разрешённых связанных задач, текущий changelog показан только локально; карточка выпуска и GitHub не изменяются. |
| Сопроводительное письмо | владелец, этапы | TXT для контакта, закреплённого в клиентском заказе; адрес проверяется локально, в API не передаётся, отправки нет. |
| Изменение сметы | владелец, этапы | Изменение одного этапа только предложения в `draft` через `client.stage`; новая сумма задаётся пользователем, валюта и срок остаются. Сервер вычисляет исходный и новый итог; модель предлагает только название и объём работ. Опубликованная смета неизменна. |
| Список разногласий | legal.write, редакции | TXT для юридической проверки изменений метаданных редакций; не анализ текста PDF и не изменение договора. |

Уточните задание и сформируйте новый черновик, если предложенный текст не подходит. Подтверждение — отдельный POST с CSRF, одноразовым случайным идентификатором и явным согласием. Перед записью сервер проверяет действующую сессию, MFA, права, политику, срок, получателя и SHA-256 исходной выборки/объекта; конфликт требует нового черновика. Для действий в БД проверка и мутация выполняются в одной транзакции с существующей блокировкой записи, доменные команды используют вложенный savepoint. Двойной POST не создаёт вторую запись; журнал `action_log` и аудит содержат тип, идентификатор, отпечаток и результат, но не полный текст. Текстовые выгрузки не хранятся в БД, не отправляются и не публикуются; если скачивание не завершилось после подтверждения, создайте новый черновик. Внешние действия, подпись, платёж, деплой и публикация требуют штатных маршрутов.

Один ожидающий черновик хранится в серверной PHP-сессии не дольше 15 минут доступности, независимо от срока истории ответов (в том числе при нуле). При отмене, подтверждении, смене политики владельцем, переключении организации, выходе или следующем запросе после TTL состояние очищается. Неактивные файлы сессий удаляются штатным GC PHP; это не гарантия физического удаления файла через 15 минут. Настройте защиту и очистку каталога сессий по AUTHENTICATION.md. Сохранённые пользователем TXT и созданные бизнес-записи подчиняются обычной политике хранения, а не TTL AI-истории. Запросы расходуют те же квоты; API вызывается только при подготовке, не при подтверждении. Данные подтверждения не передаются модели.

### Приёмка 1.3.2

Запустить `php tests/assistant_draft_unit.php`, `php tests/assistant_draft_db.php`, PostgreSQL-ветку `assistant_draft`. На стенде проверить все шесть видов с реальным API: до подтверждения бизнес-записи неизменны, после подтверждения ровно одна задача/правка, повторный POST не создаёт действие, смета остаётся draft, TXT корректно выгружается, адресат и прежние значения видны, неверные ссылки/истёкший TTL/отзыв роли/MFA/смена политики/изменение версии блокируют запись. Проверить, что закрытый проект и соседняя организация не попадают в запрос или предпросмотр. Сравнить точные суммы с карточкой сметы. Включить доказательства в `assistant_confirmed_drafts` регламента PRODUCTION.md. Старые проверки чтения и ролевой политики остаются обязательными.
