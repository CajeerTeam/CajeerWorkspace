# Экономика проекта · 0.5.3

Раздел «Экономика» доступен по финансовым полномочиям проекта. Для просмотра и записи в Web требуется свежий MFA; настройки изменяет только владелец организации. Учет не является налоговым, регламентированным или полным учётом начислений. Не создаёт проводок, платежей, банковских переводов или счетов.

## Настройка и бюджет

1. Выберите проект, месяц факта и горизонт прогноза (сегодня — 366 дней вперёд, по умолчанию 90 дней).
2. Выберите модель выручки: почасовая, фиксированная или без признания. Она одна на проект. Смена модели пересчитывает исторический управленческий отчёт, не меняя первичные записи. При смешанной модели разделите работы на проекты; автоматического смешанного признания нет.
3. Введите месячный бюджет отдельно по валюте: выручка, себестоимость труда, прямые расходы. Сравнение «факт − план» сохраняет знак. Бюджет редактируется с проверкой версии; актуальная редакция отображается в отчёте, изменение отмечается в аудите. Исторические версии бюджета как отдельные снимки не сохраняются.
4. Введите внутренние ставки сотрудников с датой начала действия и валютой. Нулевая ставка допустима (например, добровольческий вклад). Новая ставка добавляется, прежняя не меняется. Первую ставку или ставку до самой ранней можно установить для ранее не оценённой работы; новая ставка после существующей не может затронуть уже отправленную/утверждённую работу. Ставка выбирается на дату выполнения записи, а не на дату утверждения.
5. Классифицируйте фактические расходы кассовой книги: прямые, расчёт за труд (исключить во избежание повторного включения себестоимости) или прочие (не входят в валовую маржу). Для сторно действует классификация оригинала. Возврат оплаты счёта учитывается в денежном потоке, но не считается прямым расходом. Неизвестные расходы и минуты без ставки отмечаются; маржа предварительная, пока они не разобраны.

## Формулы и первичные записи

- **Выручка почасовая**: `timesheets.cost_minor` из утверждённого снимка клиентской цены (несмотря на историческое имя поля, в данном отчёте это цена работ для клиента); только таймшиты с `rate_mode=hourly`. Без сохранённой цены часы отображаются как неоценённые. Выручка относится к месяцу утверждения UTC.
- **Фиксированная выручка**: цена принятого этапа из принятой редакции предложения, один раз по дате принятия `client_deliveries.decided_at`. Полная цена принятых предложений показывается отдельно; текущая фиксированная ставка проекта без принятых этапов справочная, не признанная выручка. Часы при фиксированной модели не умножаются на цену договора.
- **Себестоимость труда**: согласованные минуты группируются по таймшиту и датированной внутренней ставке; `round(minutes × hourly_minor / 60)` до ближайшей минорной единицы, половина вверх. Отнесение к месяцу утверждения UTC. Стоимость клиента и внутренняя себестоимость не смешиваются.
- **Прямой расход**: проведённые расходы с категорией `direct`, включая отрицательное сторно, по дате кассовой записи. Без классификации не входит в маржу. Расчёты зарплаты не дублируют трудозатраты.
- **Валовая маржа**: выручка минус себестоимость труда и прямые расходы. Процент = маржа / выручка × 100 (только если выручка положительна). Процент округляется для отображения. Все суммы рассчитываются в целых минорных единицах, отдельно по RUB/EUR/USD/PLN/GBP. Суммарной мультивалютной маржи нет; при разных валютах выручки и затрат результаты по отдельным валютам не являются итоговой рентабельностью проекта. Не выполняется переоценка или FX-конвертация.
- **Cash-flow**: начальный накопленный остаток кассы проекта + проведённые поступления − проведённые расходы; сторно учитывается со знаком. Это накопленный кассовый результат, не остаток банковского счёта. Долг клиента и признанная выручка не увеличивают полученные деньги. Факт текущего/будущего месяца ограничен сегодняшней датой.
- **Дебиторская задолженность** на сегодня: сумма выставленного счёта − проведённые оплаты + возвраты; аннулированные и черновые счета исключены. Возврат не отменяет приёмку работ; корректирующие документы и сторно выручки не автоматизированы.

Отчёт содержит ссылки/ID таймшитов, этапов/приёмок, счетов, кассовых записей и ставок. Первые 100 строк источников выводятся для детализации, суммы включают все записи. Кассовая книга и реестр счетов доступны отдельно. Для классификации расхода вне первых 100 строк есть форма по ID. Операции доступны только внутри проекта/организации.

## План платежей

Автоматический прогноз включает неоплаченные остатки выставленных счетов до горизонта, в том числе просроченные, без отдельного прибавления ожидающих согласования оплат. Ручные планы предназначены для других доходов и расходов, не для повторного ввода выставленных счетов. Для исполнения вручную привяжите проведённую кассовую запись по ID: проект, направление, валюта и сумма должны совпадать, допускается несколько частичных движений. Платёж по счёту не может быть привязан повторно к ручному плану. Одна кассовая запись — один ручной план. Сторно автоматически восстанавливает остаток плана. Ошибочную привязку можно снять с основанием; кассовая запись при этом не меняется. Можно перенести срок и изменить сумму (не меньше уже проведённого). План без проведённых средств можно отменить.

Прогноз остатка = текущий кассовый результат + ожидаемые поступления − ожидаемые расходы. Календарь показывает накопительный прогноз по валюте после каждой операции; просроченные остатки считаются подлежащими исполнению с текущего момента. Это сценарий полного исполнения плана, не гарантия доступности денег. Не вводите ручной план на уже выставленный счёт. Неоплаченные счета без наступившего срока после горизонта включены в долг, но не в прогноз.

## Обновление и приёмка

Схема 018 добавляет шесть таблиц и не редактирует старые записи. Выполните `php bin/workspace doctor`, `php bin/workspace upgrade` (предварительный снимок SQLite; PostgreSQL — проверенный pg_dump до запуска). `php bin/workspace migrations` должен показать 18 применённых миграций.

`python3 tests/economics_schema.py` проверяет миграцию, сохранность старых данных/PDF и ограничения. `php tests/economics_db.php` выполняет сценарий бюджета, часов, изменения ставок, частичной оплаты, прогноза, сторно, фиксированного заказа, прав и UI. В PostgreSQL CI также выполняется `php tests/economics_db.php --postgres` с переносом и сверкой итогов. Для полного запуска нужны расширения PDO SQLite, cURL и (для переноса) PDO PostgreSQL, сервер PostgreSQL.
