# Книги проекта — EngineBook 1.2.0

Поддерживается публичный Reader из CajeerEngineBook 1.2.0 (исходники `src/App.php`, `src/BookStore.php`, `src/Visibility.php`, `src/PostgresContentStore.php`). Сервисный токен CI предназначен для публикации и не используется для чтения закрытых книг. Не настраивайте обход авторизации. API возвращает опубликованные страницы, а не исторические номера Studio.

В `config/connections.local.json` настройте, например:

```json
{"book":{"base_url":"https://docs.example.com","installed_version":"1.2.0"}}
```

Для отдельного публичного workspace допустим адрес `https://docs.example.com/w/<32 hex org>/<32 hex workspace>`. HTTPS обязателен, HTTP только на loopback для тестов. Адрес назначает оператор; нет перенаправлений, cookies, пользовательских URL и ключей. Используются `GET /api/v1/pages` (объект, ключи book/version/path) и `GET /api/v1/pages/{book}/{version}/{path}`. При смене адреса создайте новое подключение с новым ключом, старую привязку отключите. Сведения о версии устанавливает оператор.

1. Войдите с MFA. Владелец открывает «Книги», выбирает проект и привязывает `handbook/1.0` (реальные slug/version). Привязка также назначает подключение проекту.
2. Пользователь с work и connections просматривает исходный Markdown и выбирает 1–12 страниц, двух разных рецензентов с теми же правами, задаёт имя. Содержимое каждого ответа фиксируется вместе с ключом, ID страницы, title, section, order, locale, updated, media IDs, Markdown и SHA-256. Каталог сверяется с метаданными прочитанных страниц. Весь снимок (до 2 МиБ, до 256 КиБ Markdown на страницу) канонизируется и хешируется. Повтор одной формы не создаёт второй снимок. Несогласованная подборка не заменяется.
3. Каждый рецензент (не автор) открывает точный снимок и утверждает либо возвращает с комментарием. Два approve требуются для approved; changes завершает маршрут. Для исправления создайте новую подборку после публикации исправлений в Book. Решения неизменяемы и относятся к SHA-256 снимка.
4. Владелец/менеджер с manage и connections связывает утверждённую подборку с подтверждённым выпуском 0.4.1. Проверяются права рецензентов, активное поколение репозитория, хеш доказательств релиза. Сохраняются release ID, тег, commit SHA, evidence hash и snapshot hash. Один снимок на привязку книги и выпуск, без перезаписи; ссылки появляются в карточке релиза. Редактирование Reader не меняет содержимое локальной ссылки.

Все веб-операции требуют свежего MFA, POST защищены CSRF. При отключении источника, снятии проектной связи или изменении конфигурации локальные снимки и ссылки недоступны, но данные остаются в базе. Доступ к сохранённым снимкам управляется Workspace; последующее изменение публичности на удалённом сервере не удаляет копии. Оператор обязан отключить привязку, если документация стала закрытой. JSON выгружается в точных байтах сохранённого снимка, его SHA-256 можно проверить sha256sum. Рендеринг безопасный текстовый; Markdown и HTML не исполняются, медиа не скачиваются (фиксируются идентификаторы), внешние ссылки и OpenAPI-ресурсы не архивируются. API Reader не предоставляет атомарный многодокументный снимок, поэтому подборка фиксирует отдельно прочитанные версии, а не глобальное состояние Studio. Независимые рецензенты подтверждают фактически сохранённый комплект. Нет записи или публикации в EngineBook.

Миграция 025 для SQLite и PostgreSQL. Приёмка: тесты `tests/book_db.php`, `tests/book_schema.py`, для PG `tests/book_db.php --postgres`. На стенде настройте настоящий публичный Reader 1.2.0, проверьте каталог, отказ при закрытом Reader, две рецензии, ссылку релиза после изменения опубликованного текста и отключение привязки. Тестовый транспорт в тестах не является производственным API.
