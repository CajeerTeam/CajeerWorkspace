# 1.7.0 — Delivery & Operations Integrations

Откройте выпуск, карточку поставки, историю деплоев или связанный инцидент и перейдите в «След выпуска и эксплуатации». Требуются проектное право `connections` и свежее MFA. Выберите конкретное задание: одинаковый SHA не делает две установки одним наблюдением. В обычном режиме используются только сохранённые доказательства. Не происходит автоматического деплоя, закрытия инцидента или изменения подтверждённого выпуска.

## Источники и доверие

- GitHub: подтверждённый выпуск, активное поколение привязки и SHA-256 сохранённого evidence. По явному запросу scoped GitHub App перечитывает тег, опубликованный Release и конкретный asset; сверяет SHA, metadata digest, размер, ID, changelog и повторно разрешает тег. Не повторяет CI и не скачивает байты артефакта. Ошибка/отзыв/изменение не заменяются прежним успешным ответом.
- Деплой: `target_snapshot`, точный release ID и evidence hash, `result.after` и `result.after_digest` от доверенного исполнителя. Последняя неотменённая попытка и равенство текущей привязки обязательны для статуса последнего управляемого деплоя. Более новый queued/failed/recovery_required также исключает текущий статус.
- aaPanel и Servers: хост, ID и имя сайта, workspace/asset UUID; инвентарь читается только из совпадающих настроенных привязок, со сроком 15 минут и без текущей незавершённой синхронизации. Показываются домены, сертификат, статус ресурса. Владелец обновляет оба источника штатной сверкой инфраструктуры. Неизвестный статус не считается online. Значения окружений сравниваются буквально с dev/staging/prod; нестандартный непустой код явно отмечается как несовпадение. Инвентарь не измеряет uptime, HTTP-ответ или актуальные байты приложения после внешнего изменения.
- Logs: до 100 локальных записей доставки с сохранёнными request ID, correlation ID, состояниями и remote event UUID в пределах retention. Явное чтение Logs ограничено 7 днями или меньшим retention, одной страницей до 50 результатов; фильтры по release, environment, job, host, correlation и повторная локальная проверка. Совпадение с локальной записью требует request ID, correlation, event и времени. Сырые сообщения, credential, другие объекты и чужие проекты не выводятся. Отсутствие событий в выборке не является подтверждением исправности.
- Incidents: точная связь по release ID, job ID, host ID, environment и нормализованному сигналу `deploy.failed` / `deploy.recovery_required`. Сигналы aaPanel/Servers сайта выводятся отдельно как контекст, не как причина выпуска. Реальный отказ доверенного исполнителя при активной политике дежурства регистрируется даже без записи сервиса; для сервиса сохраняется SLO-привязка. Неуспешная предварительная проверка и неподтверждённое сообщение Logs сами по себе не создают инцидент управляемого деплоя. Одна карточка на задание, повторная обработка не создаёт дубликат; сохраняются прежние исторические решения. При отсутствии сервиса автоматическая сверка ограничена отказами после настройки текущей политики дежурства. Ручное закрытие требует действующего процесса инцидентов.

## Приёмка

На отдельном стенде с GitHub App Contents read, реальным aaPanel, выделенной сессией Servers и раздельными read/write credentials Logs: подтвердить релиз, развернуть в staging, выполнить сверку инфраструктуры, отправить события существующим Logs worker. На странице проверить точное соответствие ID, SHA и digest и сохранённые квитанции. Проверить другой деплой того же выпуска на другом сайте/хосте; его события не должны попадать в выбранное задание. Сменить тег, выключить привязку, создать более новый деплой, дождаться устаревания инвентаря: прежние доказательства не должны выдаваться как текущие. Сымитировать отказ управляемого деплоя с активной политикой и без сервиса, затем просканировать инциденты; убедиться в отсутствии дубля и наличии ссылки. Повторить с сервисом, сверить SLO. Проверить отзыв доступа, MFA, скрытие сырых сообщений и отсутствие межпроектных связей.

`php tests/release_trace_unit.php`, `php tests/release_trace_db.php`, `php tests/delivery_db.php`, `php tests/service_ops_db.php` (также `--postgres` в CI), `php tests/logs_db.php`, `php tests/incidents_db.php`.

Схема 50 и все 100 SQL-файлов неизменны. Перед переходом сделайте проверенную резервную копию. Реальные внешние API и эксплуатационный допуск проверяются отдельно.
