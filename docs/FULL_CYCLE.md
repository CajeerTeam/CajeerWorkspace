# Приёмка полного цикла 1.8.0

Это исполняемый контроль сохранённых связей и доказательств, не симулятор провайдеров и не автоматический допуск реального стенда. Схема 51. Не запускайте на рабочей организации. Используйте отдельный staging, отдельные БД, секреты, тестовые аккаунты/ресурсы и `WORKSPACE_PILOT=1`. См. PILOT.md, PRODUCTION.md, RECOVERY.md. Выполнять с доверенной CLI на остановленной для записи площадке при формировании окончательных отчётов; внешний обмен и worker должны быть завершены. Не копируйте реальные персональные данные в пилот.

## 1. Топология

Создайте первичного владельца и `pilot:seed` по PILOT.md. После seed:

```sh
umask 077
php bin/workspace pilot:boundary OWNER_ID < /secure/private-second.json
```

Файл содержит `email`, `name`, `password`, `organization`, `project`; отдельный владелец, уникальный пароль, отличные от первичной организации. Не храните файл в репозитории. Команда создаёт независимую организацию, владельца, внутренний проект, задачу и событие аудита в одной транзакции. Повтор отклоняется. Во второй организации нет подключений первой. Это контрольная организация, основные рабочие сценарии выполняются в первой. Не добавляйте общих участников. `pilot:check` по-прежнему проверяет восемь сотрудников, два состава команд, три проекта первой организации и гостя.

## 3. Машинный отчёт

Укажите реальные ID (все положительные целые, три разных задания и два разных маршрута):

```json
{"order":1,"delivery":1,"invoice":1,"statement":1,"contract":1,"signature":1,"product_release":1,"staging_job":2,"production_job":3,"failed_job":1,"oss_release":1,"engine_route":1,"lite_route":2}
```

Это только пример формы, не готовые доказательства. Сохранить собственные ID в `/secure/cycle-ids.json`.

```sh
php bin/workspace pilot:check OWNER_ID > /secure/evidence/topology.json
php bin/workspace pilot:cycle OWNER_ID < /secure/cycle-ids.json > /secure/evidence/cycle.json
php bin/workspace pilot:probe OWNER_ID > /secure/evidence/readiness.json
```

`pilot:cycle` ничего не отправляет во внешние системы. Он повторно вычисляет 15 проверок связанных объектов, 20 проверок границы организаций, 240 результатов реальных вызовов RBAC; проверяет хеши документов, кассу, отчёт сверки, квитанции, активность привязок. Отчёт не включает тексты документов, сообщений или токены. При неполноте возвращает ненулевой exit code (при отсутствии/недоступности записей возможно исключение без JSON). Исправьте условия на стенде штатными операциями, а не изменением JSON или БД. Хеш checker привязан к точному релизному архиву; отчёт имеет ограниченное окно актуальности. Подписанный `acceptance.json` включает хеш отчёта. Пять независимых подписантов всё ещё обязаны подтвердить фактические живые проверки и recovery, сверить контрольные ID и артефакты. Сохранённые данные не доказывают сами по себе работу живого API.

## 4. Изолированная регрессия

```sh
php tests/full_cycle_unit.php
php tests/pilot_db.php
python3 tools/pilot.py --previous /secure/previous/CajeerWorkspace-1.7.2.zip --lite-source /secure/lite-source
```

Предыдущий пакет должен быть полным проверенным архивом, не патчем. Регрессия не использует реальные секреты, не заявляет live acceptance. Пропущенный тест не считается успешным. Для production обязательны CI обеих СУБД, отдельно живой стенд и подписанный допуск. Не переносите результаты между разными установками и backend.
