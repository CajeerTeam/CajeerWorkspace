# Выпуски проекта · 0.4.1

Workspace ведёт управляемую приёмку существующего GitHub Release, а не публикует GitHub Release от имени пользователя. Публикация в GitHub остаётся за доверенным CI/maintainer. В GitHub App добавьте Repository permissions → Contents: Read-only, подтвердите новые права в установке. Обычный worker продолжает использовать прежний минимальный набор прав.

1. Привяжите репозиторий через `github:bind`, завершите задачи и привяжите к каждой PR через карточку задачи.
2. CI должен собрать артефакт на точном SHA выпуска, сохранить его SHA-256, создать тег и GitHub Release с файлом (asset state uploaded и digest sha256). Зафиксируйте ожидаемый SHA и digest из доверенного CI, не из неподтверждённого источника.
3. В проекте откройте «Выпуски проекта», подтвердите MFA, создайте карточку. Введите тег, SHA, changelog (тот же текст, что и GitHub Release), имя файла, ожидаемый SHA-256, обязательные точные имена CI checks и назначьте ответственного (owner или manager с доступом к проекту). Выберите до 20 завершённых задач с PR. Изменить карточку нельзя; ошибочную отмените и создайте заново.
4. Нажмите «Проверить GitHub». Проверяются активная установка, лёгкий или аннотированный тег, merge commit каждого PR и его достижимость из SHA выпуска, полная выборка latest check runs на этом SHA, наличие всех обязательных имён, завершение всех checks с conclusion success и combined status success при наличии статусов. Skipped/neutral не считаются успехом. Необходим хотя бы один check run. Проверяются опубликованный release, changelog, asset ID, размер и digest. Результаты сохраняются с SHA-256 снимка.
5. Ответственный проверяет доказательства и нажимает «Подтвердить» в течение 15 минут после проверки, с MFA. Все внешние проверки выполняются заново; при изменении снимка сохраняется новый, подтверждение требует отдельного действия. При ошибке подтверждение не проводится, карточка возвращается в draft с причиной отказа; предыдущий снимок помечен историческим. Повторное подтверждение уже принятой записи не создаёт новый выпуск. Изменённые задачи, связи, поколение подключения или отозванные права блокируют приёмку. Подтверждённые записи не редактируются через приложение.

Разрешения: чтение для project connections, изменение/проверка только manage + connections, подтверждение только назначенным ответственным. Гостевые и публичные OSS маршруты не получают данные. Аудит фиксирует create/verify/reverify/failed/confirm/cancel. После отключения или повторной привязки GitHub удалённый снимок скрыт; сохраняется внутренний исторический факт. Проверка синхронная, без блокировки записи БД во время HTTP; бюджет сетевых запросов 75 секунд плюс текущий запрос, настройте PHP/FPM и reverse proxy соответственно. При сетевом отказе повторите вручную. Лимит 1000 check runs и 1000 assets (для assets требуется последняя неполная страница), теги без `/`, 100 последних карточек в списке. Публикация удалённого release, скачивание байтов и проверка подписи/attestation артефакта не выполняются. Сверяется SHA-256, объявленный GitHub, с ожидаемым digest из доверенного CI; это не доказательство происхождения бинарного файла само по себе. Проверки отражают момент приёмки; перемещение тега или изменение release после подтверждения не изменяет исторический снимок. Защитите теги и используйте immutable releases на GitHub.
