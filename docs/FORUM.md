# CajeerEngineForum · 0.7.2

Поддерживается **Forum Edition 1.6.0 / Engine 2.1.0 / Engine API 1.1**. Это три независимых поля. Проверка `/api/v1/health` и `/api/v1/auth/me` производится на каждом открытии подключённого раздела и при записи. Не используйте общие сервисные аккаунты. API Forum — источник истинности для видимости, санкций, модерации и опубликованного содержимого. Workspace не изменяет ACL форума.

## Настройка

В `connections.local.json` укажите отдельную установку без пути (HTTPS; HTTP только loopback):

```json
{"forum":{"base_url":"https://forum.example.com","installed_version":"1.6.0","version_path":"/api/v1/health","version_field":"edition_version"}}
```

### Готовность и версия редакции (Workspace 1.0.1)

`sync forum` сначала выполняет `GET /health/ready` (ожидается `status: ready`), затем `GET /api/v1/health` и читает **edition_version**, а не `version` ядра. При отказе readiness второй запрос не выполняется. Если readiness успешен, но поле отсутствует, некорректно или второй маршрут возвращает ошибку, сервис остаётся «Доступно» (`ok=1`, `sync` код 0 для этого экземпляра); в результате явно указано «версия не подтверждена», `observed_version=null`, отдельная причина в `version_error`. Последняя известная версия остаётся исторической, а версия оператора не подставляется вместо наблюдаемой. `profile --check` фиксирует замечание и возвращает 1; `pilot:probe` помечает экземпляр `version_check_failed`, что не допускает production-приёмку. Это не отменяет проверок версии ядра, редакции и Engine API при прикладных операциях Forum.

В защищённом каталоге вне docroot создайте JSON, например `/srv/workspace-config/forum-identities.json`, права чтения только у администратора и пользователя PHP-FPM. Укажите `WORKSPACE_FORUM_IDENTITIES` с этим абсолютным путём. Ключи — подключение, затем `organization_id:user_id` Workspace. `user_id` внутри — UUID **реального соответствующего пользователя Forum**, не UUID владельца установки. Пример:

```json
{"forum":{"1:1":{"user_id":"11111111-1111-4111-8111-111111111111","token_env":"WORKSPACE_FORUM_OWNER"},"1:2":{"user_id":"22222222-2222-4222-8222-222222222222","token_env":"WORKSPACE_FORUM_MEMBER"}}}
```

В Forum выдайте токен каждому отдельному пользователю (срок, права по минимальной необходимости), например на стороне Forum:

```sh
php bin/console api-token:create --user-id=ACTUAL_UUID --name=workspace-personal --scope=forum:write --expires='+30 days'
```

Для назначенного модератора дополнительно `--scope=forum:moderate`, только если право действительно есть в Forum. Для читателя используйте разрешённый его роли минимальный scope, без `forum:write` и `forum:moderate`. Не выдавайте `*`. Передайте полученные токены в соответствующие переменные окружения FPM; не в JSON, исходный код, журналы, URL или БД. При увольнении/отзыве удалите соответствие и отзовите токен в Forum. Смена UUID требует отдельной проверки оператором. Не создавайте дублирующие конфигурации одного origin с общими токенами. ACL Forum действует даже при наличии локального права владельца Workspace. Запрещено привязывать общий аккаунт к разным пользователям внутри одного подключения и через алиасы одного origin.

## Работа

Владелец выбирает проект, подключение и UUID доступного раздела. Можно отключить привязку без удаления исторических идентификаторов. Менеджер создаёт тему или связывает существующую с задачей или подтверждённым выпуском того же проекта. На один источник и карточку — одна тема. Содержание карточки не передаётся автоматически: отправитель вводит заголовок и текст явно. Не публикуйте внутренние данные в общедоступном разделе. Обратные ссылки из карточек ведут в раздел с проверкой ACL; они не показывают названия или счётчики закрытых тем.

В разделе Forum отображаются связанные темы на текущей странице списка раздела; поиск выполняется удалённым `/forum/search` с `board_id`, без локальной индексации. Переходы страниц ограничены 100. Результаты, отсутствующие в текущем ответе Forum, не показываются; при сетевой ошибке закрытый контент не берётся из кеша. Карточка темы запрашивается непосредственно по UUID; перенаправленная или перенесённая за границы привязанного раздела тема скрывается. На странице обсуждения показаны авторы видимых профилей текущей страницы, текст сообщений экранируется. Игнорируемые авторы скрыты. HTML, вложения и изображения не проксируются; открывайте их в штатном интерфейсе Forum. Подписка на тему, жалоба на сообщение, ответ, закрытие/открытие и закрепление/открепление вызывают настоящие API Forum. Управление группами, приватными разделами, сложными делами модерации (включая одобрение заявок) выполняется в Forum, а не через расширенные права Workspace.

При предварительной модерации ответ API содержит `pending_review` и `submission_id`. Для новой темы автор вызывает «Сверить»: первые пять страниц личных заявок, статус `approved` и `result_id` с повторной проверкой доступа к теме. Если заявка отклонена или отменена, можно создать тему в Forum и привязать её вручную. Для ожидающих ответов статус операции показывает приём заявки; дальнейшая проверка ответов в штатном кабинете Forum. При неопределённой отправке (`sending` после сбоя или `uncertain`) не повторяйте POST. После 60 секунд автор может перевести зависшую отправку темы в `uncertain` и вручную связать обнаруженную тему. Для отказа/неопределённости при ответе проверяйте Forum перед новой формой. Повтор того же ключа запроса не отправляет операцию второй раз; новый ключ — отдельное намерение. Никаких автоматических повторов записи.

В БД только связи, идентификаторы, хеш намерения, статус и журнал; нет текстов, заголовков, снимков и токенов. Аудит хранит локальные номера и результат, без удалённых данных. Приватность ранее прочитанного/скопированного текста не может быть восстановлена удалённым отзывом. Проверки доступа и записи в разных системах не составляют распределённую транзакцию; окончательное решение принимает Forum при каждой операции. Полная приёмка требует реального стенда с публичным и закрытым разделом и проверкой отзывов прав, санкций, модерации и TLS.
