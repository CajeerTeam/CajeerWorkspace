# Хранение и выдача · 0.6.3

## Политики и Legal Hold

В разделе «Хранение» владелец организации с MFA создаёт политику: двухбуквенный код страны, тип PDF, срок в днях (1–36525), основание. Это конфигурируемое правило организации, не автоматически обновляемый справочник законодательства. Юрист проверяет применимость срока и момент его начала до назначения. Новые политики не изменяют старые автоматически; без явного назначения удаление запрещено. Назначение распространяется на все редакции документа; для каждой отсчёт идёт от более поздней из UTC даты загрузки и явно указанной даты начала хранения (например, даты окончания договора). Пока момент начала неизвестен, не назначайте срок либо установите удержание. Срок назначенной политики и дату начала можно только увеличить/отодвинуть, страну менять нельзя. Сохранены записи политики и аудит назначения.

Удержание (Legal Hold) устанавливается владельцем с основанием спора. Можно иметь несколько одновременных удержаний: очистка разрешается только после снятия каждого с основанием. Удержание действует на все версии, даже новые, и не ограничивает правомерное чтение или перенос без потери байтов. Подписанные оригиналы, квитанции и исходники, на которые ссылаются договоры, приложения, согласования, клиентские результаты или гостевые приглашения (даже исторические/отозванные), не удаляются этой версией. Никакого каскадного удаления. При необходимости регламентированного удаления таких комплектов требуется отдельная процедура. Позднее удержание не восстанавливает уже удалённый файл.

Проверка перед очисткой повторяется в транзакции. После истечения срока неиспользуемая редакция может быть удалена через интерфейс с явным подтверждением или CLI. Остаётся неизменный SHA-256, размер, идентификатор версии, дата, аудит и запись `purged`; новые привязки и выдача запрещены. В БД содержимое заменено служебным маркером, внешняя копия удаляется только после фиксации маркера. При сбое удаления внешний ключ сохраняется для повторной очистки; активный Legal Hold блокирует и повторную физическую очистку. Не является гарантированным стиранием с носителя, WAL, снапшотов и резервных копий. Отдельно применяйте согласованные политики к резервным копиям.

```sh
# ORG_ID OWNER_ID [LIMIT], максимум 100 за запуск
php bin/workspace retention:preview 1 1 100
# Только после утверждения результата/резервирования:
php bin/workspace retention:cleanup 1 1 100
```

## Приватное объектное хранилище

Первый штатный backend — отдельный приватный каталог Linux/POSIX. Каждый PDF хранится как отдельный неизменяемый объект со случайным 256-битным ключом. Это файловое объектное хранилище, не S3/MinIO API. Для нескольких узлов необходимо единое надёжное POSIX-хранилище, поддерживающее атомарные hardlink, fsync файлов/каталога и согласованное чтение, либо один узел. Не размещайте каталог под document root веб-сервера или внутри репозитория; запретите прямую HTTP-выдачу, включите шифрование тома при необходимости. Доступ только выделенному пользователю PHP-FPM и worker. Пример (имя системного пользователя адаптировать):

```sh
install -d -m 0700 -o workspace -g workspace /srv/workspace-objects
# Одинаковая настройка PHP-FPM и CLI:
export WORKSPACE_OBJECT_DIR=/srv/workspace-objects
# ORG_ID OWNER_ID [LIMIT] [MIN_BYTES] (по умолчанию 1 МиБ)
php bin/workspace retention:objects 1 1 100 1048576
```

Перенос возможен также отдельно через карточку версии, включая подписанный оригинал. Записывается временный файл, проверяется запись и fsync, объект атомарно публикуется без перезаписи, выполняется fsync каталога и повторное чтение с проверкой SHA-256. Только после этого в транзакции заменяется содержимое БД на непечатный для PDF маркер. Чтение, согласование, клиентская выдача и подпись используют единый резолвер; повреждение/отсутствие объекта вызывает отказ. Восстановление в БД проверяет байты и SHA-256, сохраняет внешний объект как резервную копию, привязанную к записи; следующий перенос повторно использует его после проверки. Удаление очищает и эту копию. Лимиты исходных PDF (2 МиБ) и подписанных PDF (16 МиБ) не изменены. Объектное хранение применяется к PDF, не к JSON-квитанциям; хеш полного выдаваемого комплекта доказательств вычисляется при подготовке в защищённом временном потоке.

Не очищайте каталог по возрасту файлов, не изменяйте объекты вручную. Неудачная транзакция после публикации может оставить непривязанный объект; он не доступен из Workspace. Удалять такие объекты только в остановленном приложении после проверки всех БД, резервных копий и удержаний. Не используйте общую директорию для разных независимых установок. Смена `WORKSPACE_OBJECT_DIR` без переноса содержимого запрещена.

### Резервирование и восстановление

Команда `backup` сохраняет БД, но **не** внешний каталог. Остановите приложение и все worker/cron, сделайте проверенный SQLite backup / pg_dump и защищённую копию всего каталога объектов как единую пару. При восстановлении используйте эту пару и ту же настройку каталога. Проверьте обычную выдачу, подписанные оригиналы и SHA-256 контрольных файлов. `postgres:import` переносит указатели и проверяет доступные объекты; объектные байты остаются в том же хранилище, либо должны быть скопированы отдельно. Не восстанавливайте более старый снимок БД с более новым очищенным каталогом. До запуска 0.6.2 нужен откат согласованного снимка схемы 22 и кода, а не просто замена PHP.

## Временные ссылки и выдача

Владелец с MFA выбирает конкретную редакцию или подписанный оригинал и создаёт ссылку на 1–10080 минут, 1–20 выдач. Это bearer-доступ: любой обладатель может скачать файл; не отправляйте ссылку в общие каналы. Токен 256 бит, в БД только SHA-256. Ссылка показывается один раз после создания; повтор формы не создаёт ещё одну ссылку. GET показывает страницу подтверждения без расхода лимита, POST проверяет срок/отзыв/лимит и текущие полномочия издателя, читает и проверяет байты, атомарно увеличивает счётчик и регистрирует выдачу. Отзыв выполняется из карточки; удаление исходной редакции отзывает все её ссылки. Не выдавайте тестовый подписанный PDF как юридический оригинал.

Используйте HTTPS. Для маршрута `?p=retention.share` настройте исключение query string и тела запроса из логов reverse proxy/APM и не включайте стороннюю аналитику. Ссылки не содержат пользовательских ID; приложение отправляет `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, выдачу только как attachment. Права внешнего получателя ограничены конкретными байтами, а не проектом. Журнал хранит дату, редакцию, пакет (если применимо), канал, ID сотрудника/гостя/ссылки, размер и SHA-256 фактически подготовленного ответа. Фиксация означает разрешённую сервером выдачу, а не доказательство завершённого скачивания или личности обладателя ссылки. Внутренние права на обычные PDF, клиентские файлы, акты и подписанные оригиналы сохранены. Журнал доступен юридическим читателям в пределах проекта, изменения политик/удержаний/ссылок/хранилища — только владельцу с MFA. CLI выполняется доверенным системным оператором с проверкой действующего владельца указанной организации.
