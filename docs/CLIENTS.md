# Клиенты и заказы · 0.3.2

## Рабочий процесс

1. Создайте проект типа «Клиентский». Войдите владельцем организации, подтвердите TOTP в разделе «Безопасность», откройте «Клиенты и заказы».
2. Создайте контрагента, заполните его регистрационные реквизиты и контактное лицо (имя, проверяемый формат email, телефон). Редактирование справочника не изменяет снимок имени контрагента и контакта в уже зарегистрированном заказе.
3. Зарегистрируйте полученный запрос в рамках проекта. Создайте предложение с условиями и валютой; добавьте один или несколько этапов с объёмом/критериями приёмки, сроком и ценой. Смета — сумма цен этапов в одной валюте. Денежные значения сохраняются в минорных единицах. Не более 100 этапов в редакции; общая сумма не выше 999 999 999,99.
4. Для входа клиента настройте SkiF4er ID согласно [AUTHENTICATION.md](AUTHENTICATION.md), загрузите разрешённую клиенту редакцию PDF (например, предложение). В карточке **конкретного заказа** выдайте приглашение, выбрав этот PDF. Передайте код и ссылку на гостевой вход защищённым каналом. Срок кода 1–168 часов, доступ после принятия — 30 дней. Email подтверждается поставщиком OIDC и должен совпадать со снимком контакта. Старая ссылка на общий проект не предоставляет доступ к заказу. Унаследованное ограничение — одна активная гостевая учётная запись на OIDC-идентичность; для другого заказа нужно отозвать предыдущий доступ. История решений при этом сохраняется.
5. Отправьте смету клиенту. Черновик до отправки невидим для клиента; после отправки редакция неизменяема. Клиент принимает или отклоняет предложение из кабинета. Для отклонения обязательна причина. После отклонения владелец создаёт новую редакцию; старые редакции и решения сохраняются. После принятия предложение фиксируется. Отдельное допсоглашение или изменение уже принятой цены пока не предусмотрено.
6. Привяжите к каждому принятому этапу задачи этого проекта (одна задача относится не более чем к одному этапу). Ведите время в существующих таймшитах и согласовывайте его по правилам 0.3.1. Для сдачи нужно завершить все связанные задачи. Состав задач фиксируется при первой сдаче. Владелец публикует описание результата, при необходимости выбирает конкретную редакцию PDF проекта. Для клиента этот файл доступен только через его заказ. Публикуйте только предназначенные этому заказчику документы и сведения.
7. Клиент принимает результат или возвращает его с комментарием. При возврате сохраните исправленный результат новой сдачей. При принятии проверяется завершённость задач и фиксируется список **уже утверждённых** записей времени по задачам этапа, их минуты, дата решения, приглашение клиента, сумма и объём из принятой сметы. Позднее утверждённые часы не изменяют снимок. Неутверждённые часы в принятый объём не включаются, поэтому перед приёмкой согласуйте нужные таймшиты. История принятых результатов не редактируется.

## Границы доступа

Коммерческий справочник, сметы и операции с заказами доступны только владельцам своей организации с актуальным MFA. Это намеренно не расширяет полномочия менеджера на финансы. Исполнители продолжают работать через задачи и таймшиты. Клиент видит только свой зарегистрированный запрос, опубликованные предложения, смету, этапы и опубликованные результаты, а не внутренние задачи, ставки сотрудников, финансы, другие заказы или проекты. Решения клиента требуют действующей OIDC-сессии, CSRF и актуальной версии; повтор того же решения не дублирует результат. История гостевых решений хранится с ID приглашения и временем отдельно от аудита внутренних пользователей (гость не получает внутреннего пользователя). Отзыв приглашения блокирует решения и скачивание. Старые PDF-приглашения работают как раньше. Текстовые данные экранируются, PDF выдаётся с проверкой хеша.

Смета — договорная оценка этапов, не счёт и не кассовая операция. Связь с расчётом часов не изменяет фиксированную цену этапа. Юридическое подписание, счета и ЭДО относятся к следующим версиям. Запрос на этом этапе регистрирует владелец по обращению клиента; отдельная публичная форма лидов, рассылка email и самостоятельное создание заказов гостем не входят в релиз.

## Обновление и проверка

Миграция 009 добавляет 9 таблиц, не меняя данные ранее выпущенных схем. Остановите приложение и фоновые процессы, сделайте резервную копию, обновите по [UPGRADE.md](UPGRADE.md). SQLite создаёт дополнительный предварительный снимок автоматически; PostgreSQL требует проверенный pg_dump до upgrade. Для импорта SQLite → PostgreSQL используется штатный `postgres:import`, включая новые таблицы и существующие PDF; сравниваются число строк и хеши.

`python3 tests/clients_schema.py` — сохранность и ограничения SQLite; `php tests/clients_db.php` — бизнес-сценарий и локальная обработка подтверждённой OIDC-идентичности; `python3 tests/clients_e2e.py` — HTTP-сценарий владельца и изоляция; `php tests/clients_db.php --postgres` — перенос с проверкой данных и последовательностей. Полная проверка живого входа через SkiF4er ID требует зарегистрированного клиента и реального тестового аккаунта.
