# Инфраструктура · 0.4.2

## Подготовка

Оператор ОС настраивает HTTPS и существующие именованные подключения в `config/connections.local.json` (или `WORKSPACE_CONFIG`). Для aaPanel включите API, IP allowlist и ключ. Для CajeerServers 1.0.2 используйте выделенную серверную сессию пользователя с правом `inventory.assets.read` и членством в целевом workspace; опубликованный Inventory GET использует sessionAuth, не произвольный bearer. Передайте **имя и значение** действующего cookie `NAME=VALUE` через указанную переменную окружения, не через UI или URL. Срок жизни и обновление cookie определяет CajeerServers; при истечении снимок маркируется устаревшим. Не помещайте ключи и cookies в JSON или репозиторий. Пример (фрагмент):

```json
{
  "panel-prod": {"type":"aapanel","base_url":"https://panel.example.com:7800","secret_env":"WORKSPACE_PANEL_PROD_KEY"},
  "servers-prod": {"type":"servers","base_url":"https://servers.example.com","secret_env":"WORKSPACE_SERVERS_PROD_COOKIE"}
}
```

Назначьте подключения соответствующей организации штатными средствами. Не регистрируйте один физический endpoint под разными DNS-алиасами. TLS проверяется; редиректы запрещены. Публичная проверка готовности CajeerServers не получает cookie.

## Работа

В проекте откройте «Инфраструктура dev/staging/prod». Владелец с MFA регистрирует окружение, хост (одна панель ↔ один asset CajeerServers, подтверждённый оператором), UUID workspace и asset из Inventory. Выбирает API aaPanel v2 или legacy. После сверки обоих источников привязывает конкретный сайт к окружению проекта. Один ID/имя сайта одного хоста не может принадлежать двум проектам. При переносе сначала отвяжите старую запись. Если имя/ID удалены или изменены, UI показывает отсутствие совпадения; автоматически привязка не заменяется. При изменении endpoint или имени env-переменной необходимо отвязать сайты, удалить хост и зарегистрировать его снова; ротация значения секрета не требует изменения связи.

Инвентарь aaPanel: `POST /v2/data?action=getData` (или `/data?action=getData`) с `table=sites`, `type=-1` и пагинацией, затем `table=domain` с привязкой `pid`. Это PHP/WP scope, а не все виды приложений панели. SSL метаданные берутся из `ssl` списка сайтов (`notAfter`, `issuer`, `dns`); `-1` означает отсутствие подтверждённых метаданных, не доказательство отсутствия TLS. Метод GetSSL не вызывается, поскольку возвращает приватный ключ. Сертификат не проверяется внешним TLS handshake. Максимум 999 сайтов, 4999 записей доменов и ограниченный бюджет времени; неполный/некорректный результат не заменяет снимок. Состояние CajeerServers читается через `GET /api/v1/inventory/assets/{id}`, проверяются оба UUID и отсутствие удаления. Параллельные опросы ограждены токеном поколения. Последний успех остаётся отдельно от последней попытки; свежесть 15 минут. При расхождении окружений показываются оба значения, без автоматической перезаписи.

Ручной опрос доступен из UI и CLI (доверенный оператор ОС указывает действующего владельца для атрибуции; аудит помечает CLI):

```sh
php bin/workspace infra:sync HOST_ID OWNER_ID
```

Код выхода 1 при отказе любого источника. Можно запускать через cron с периодом 5–10 минут, задав окружение процесса. Чувствительные изменения в UI требуют MFA. Владелец видит весь инвентарь организации, проектные читатели интеграций — только привязанные сайты и связанные хосты. Матрица задаёт ровно одного ответственного сотрудника и продукт на операцию хоста; отсутствие назначения или отключённый сотрудник отображаются явно. Это согласованная ответственность, не гарантия поддержки мутации конкретным API. Удаление непривязанного хоста удаляет его снимки и матрицу. Удалённые команды, деплой и автоматический откат относятся к 0.4.3.

## Источники API и проверка стенда

- https://www.aapanel.com/docs/api/api-list.html
- https://github.com/aaPanel/aaPanel/blob/master/class/data.py
- https://github.com/CajeerTeam/CajeerServers/blob/main/openapi.yaml (1.0.2)

На стенде: зарегистрируйте хост, сверьте, привяжите сайт, сравните домены и дату SSL с панелью. Отключите один API, убедитесь в сохранении исторического снимка и обновлении другого; восстановите API. Проверьте расхождение окружения и отсутствие доступа у другого проекта. Полная проверка совместимости зависит от фактической версии aaPanel, сессии CajeerServers и конфигурации TLS.
