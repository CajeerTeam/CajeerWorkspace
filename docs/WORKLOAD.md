# Спринты, доступность и таймшиты · 0.3.1

Откройте проект → «Спринты, загрузка и таймшиты». Выберите отчётную неделю (понедельник; даты UTC) и спринт. Для доступа требуется право работы или чтения финансов в данном проекте. Гостям раздел недоступен. Менеджер управляет спринтами, участники с правом работы могут вести собственный таймшит и доступность. Владелец может выполнять все операции, кроме согласования собственных часов.

## Планирование

- Спринт длится 1–91 календарный день; даты спринтов одного проекта не пересекаются. Запланированный спринт можно редактировать, затем начать, затем закрыть. Одновременно возможен только один активный спринт. Закрытие фиксирует состояние завершённости каждой связанной задачи; закрытый спринт неизменяем. Невыполненные задачи можно добавить в следующий спринт, не теряя старой связи. Текущие название и исполнитель задачи отображаются по её карточке; исторический снимок относится к оценке и признаку выполнения.
- Задачи добавляются по номеру, с оценкой 0–60 000 минут. Номер можно выбрать из подсказок либо взять из карточки задачи. Задача может состоять только в одном незакрытом спринте. Изменения используют версию спринта, поэтому устаревшая форма отклоняется.
- Доступность — плановое число минут **на конкретный проект за неделю** (0–10 080), а не глобальный календарь занятости. Неуказанное значение неизвестно, 0 — недоступен. Менеджер может задавать доступность действующих участников с правом работы. Участник может менять собственное значение. План спринта и недельный факт показаны раздельно: многонедельный спринт не сравнивается автоматически с одной неделей. Доступность не запрещает ввод фактически отработанного времени.

## Учёт и согласование

1. Разработчик вводит дату, номер назначенной задачи, минуты и необязательный комментарий. Менеджер может учитывать собственное время по любой задаче своего проекта. Одна запись на задачу и дату, 1–1440 минут; 0 удаляет существующую запись. Повторное сохранение меняет запись, а не добавляет ещё одну. Время в будущем и вне выбранной недели отклоняется. Сумма за сутки по всем проектам/организациям одной учётной записи не может превышать 1440 минут (без раскрытия данных других проектов).
2. Один таймшит на пользователя/проект/неделю. Черновик или возвращённый таймшит можно редактировать; при отправке проверяются права, непустой итог и ставка проекта. На согласовании записи заблокированы. Каждая отправка фиксирует сумму минут и текущую версию ставки. Не заданная ставка обозначается явно и не блокирует внутренний учёт.
3. Другой менеджер или владелец подтверждает MFA и согласует или возвращает таймшит. При возврате обязателен комментарий. Собственное согласование запрещено даже владельцу. При согласовании заново проверяется текущий доступ автора. Если доступ отозван, менеджер может вернуть заявку, но не согласовать её. После возврата автор может исправить время и повторно отправить, при этом фиксируется новая ставка. Согласованный таймшит неизменяем в этом выпуске. История действий доступна в аудите; комментарий последнего возврата хранится до новой отправки.
4. Недельный отчёт суммирует **только согласованные** минуты. Менеджеры видят таймшиты проекта и подробные записи, участник — только свои. Финансовый читатель видит согласованные итоги без комментариев и записей. Суммы и ставки видны только с финансовыми правами и свежим MFA. Отчёт не является бухгалтерской проводкой.

## Ставки

Владелец с MFA устанавливает положительную сумму и валюту RUB/EUR/USD/PLN/GBP, выбирает почасовой или фиксированный режим. Версия ставки увеличивается с каждой операцией; устаревшие формы блокируются. Почасовая стоимость рассчитывается по сумме минут всего таймшита, округляется один раз до копейки/цента по правилу half-up: `intdiv(minutes * rate_minor + 30, 60)`. Все денежные суммы хранятся целыми числами в минорных единицах. Стоимость группируется по валюте. Фиксированная цена — цена всего проекта, не умножается на часы и не суммируется по таймшитам; снимок цены сохраняется в отправленном таймшите. Изменение ставки не меняет ранее отправленный и согласованный расчёт. Не создаются кассовые записи, счета или банковские переводы.

## Приёмка и эксплуатация

Схема 008 добавляет шесть таблиц и не переписывает исходные данные. Перед обновлением остановите FPM, cron и CLI, сохраните код, конфигурацию и БД. Используйте [UPGRADE.md](UPGRADE.md); для PostgreSQL сделайте проверенный pg_dump. Новые таблицы включены в перенос SQLite → PostgreSQL с проверкой количества и SHA-256 строк. Ранее выпущенные миграции остаются неизменными.

`php tests/workload_unit.php`, `python3 tests/workload_schema.py`, `php tests/workload_db.php`, `python3 tests/workload_e2e.py` проверяют валидацию, миграцию, бизнес-логику и HTTP. `php tests/workload_db.php --postgres` дополнительно переносит тестовую SQLite в **пустую** тестовую PostgreSQL, проверяет историческую цену и последовательности. В тестовом стенде необходимы PHP PDO SQLite, cURL/OpenSSL, а для PostgreSQL — PDO PgSQL и PostgreSQL 14+. Не запускайте тесты на рабочей базе.
