# Редакторские выпуски (0.7.4)

Единый маршрут связывает одну согласованную текстовую страницу Book, подтверждённый GitHub Release, подготовленную публикацию Engine или новый путь Lite и раздел Forum. Владелец/менеджер создаёт маршрут и фиксирует Book за выпуском через `bookLinkRelease`. Снимки, рецензии, актуальность прав, хеши релиза и привязки повторно проверяются перед действиями. Создание не публикует материалы. Один маршрут на выпуск и раздел Forum; одна привязка готовой публикации Engine. Закрепление Book и создание маршрута выполняются в одной транзакции.

1. Подключите [Book](BOOK.md), подготовьте подборку, получите два независимых утверждения, подтвердите [релиз](RELEASES.md).
2. Для [Engine](ENGINE.md) подготовьте в CMS черновик с точно совпадающими заголовком и текстом Book (например, `data.body`), затем откройте предпросмотр и подготовьте публикацию в Workspace. Остальные поля черновика проверяются штатным снимком Engine; адаптер их не переписывает. Для [Lite](LITE.md) выполните `lite:inspect`, выберите новый свободный путь. Медиа не переносятся.
3. Подключите [Forum](FORUM.md), личный API token автора маршрута и нужный раздел. В «Редакторских выпусках» выберите компоненты и закрепите маршрут.
4. Подтвердите этап CMS с MFA. Engine выполняет существующий PATCH с `expected_revision`, Lite ставит существующее задание в очередь: оператор выполняет `php bin/workspace lite:work JOB_ID`. После завершения повторно нажмите «Выполнить / сверить этап CMS». Для неопределённого результата Engine выполняется только сверка; для Lite используйте `lite:reconcile`. Конфликт/отмена CMS не дают создавать обсуждение. После однозначного конфликта, отмены или abort закройте маршрут без публикации и создайте новый с той же закреплённой редакцией. Неопределённый результат требует сверки и не позволяет закрыть маршрут. Не правьте журнал SQL вручную.
5. После получения проверенного публичного адреса CMS подтвердите создание темы. Текст содержит тег и адрес опубликованного документа. Не выбирайте публичный раздел для непубличных метаданных. Опционально задайте `WORKSPACE_EDITORIAL_ORIGIN=https://workspace.example.com` (origin без пути) до создания маршрута: в тему добавится обратная ссылка на карточку релиза, защищённую обычной авторизацией Workspace. Конфигурация фиксируется при создании. Локальные обратные ссылки связывают Book, релиз, CMS, Forum и журнал; опубликованное содержимое CMS не переписывается после создания темы.
6. При HTTP-отказе или отклонении заявки нажмите «Повторить только Forum»; новый ключ попытки не повторяет публикацию CMS. Если отказ произошёл до отправки POST, обычное продолжение повторяет только Forum. При неизвестном результате не отправляйте второй POST: штатная сверка Forum и ручная привязка найденной темы авторизованным оператором; затем повторная сверка редакторского выпуска проверяет заголовок, первый пост и автора. При предварительной модерации используйте повторную сверку. Успех фиксируется при совпадении текста. Если сообщение изменено, автор скрыт или доступ отозван, проверка не проходит. Все проверки Forum выполняются с личным токеном и live ACL. Другие менеджеры не получают содержимое или состояние приватной темы через редакторский журнал.

Журнал содержит наблюдения этапов, не заменяет нативные журналы. CMS-ссылка историческая; изменения сторонними операторами после подтверждения могут изменить доступность. Engine сверяется отдельно, Lite — по нативному результату. При восстановлении Lite состояние перестаёт разрешать создание темы, но уже отправленное обсуждение не удаляется автоматически. Нет распределённой транзакции: каждый шаг сохраняется отдельно, неизвестный результат требует сверки. Управление маршрутом выполняет создатель с действующими правами, штатные администраторы могут выполнять существующие операции восстановления. Не предполагается автоматическая отправка или откат на стороне Forum.

## 1.7.1: версии, сравнение и восстановление

Поддерживаются только Engine 2.1.0 (Content API v1), Book 1.2.0 (публичный Reader v1), Lite 1.6.0 (нативная schema 14) и Forum Edition 1.6.0 (ядро 2.1.0, Engine API 1.1). `EditorialCapabilities.php` проверяет точную версию и доступную операцию адаптера; конфигурация источника уже закреплена в его `config_hash`. Неизвестная версия отклоняется. Engine/Book не заявляют автоматическое определение установленной версии: это операторская настройка и проверяемые ответы API. Forum проверяет health и личную идентичность, Lite — файл VERSION, класс и schema на хосте. Обновление внешнего продукта требует отдельной совместимой реализации и приёмки.

В карточке маршрута откройте «Сравнение редакций». Book: пустое поле ID сравнивает закреплённую страницу с текущей публичной страницей Reader, ID другой подборки — с той же страницей этой книги. Engine: подготовленный черновик или ожидаемая опубликованная редакция сравнивается с текущей записью API (включая данные и номер редакции). Lite: закреплённая страница сравнивается с каталогом последнего нативного `lite:inspect` (до 15 минут). Forum: только создатель маршрута с текущим личным ACL сравнивает ожидаемую тему с первым постом; скрытые авторы или несовпадающий principal не допускаются. Сравнение не выполняет запись, показывает полные SHA-256 и изменившийся диапазон строк между общим префиксом и суффиксом; максимум 80 строк / 16 000 байт на сторону. Это не минимальный diff всех отдельных правок. Хеши учитывают исходные байты, включая окончания строк. Не вставляется исполняемый HTML.

При отзыве источника Book или CMS маршруты не показывают сохранённое содержимое и ссылки, прямой запрос отклоняется. Сведения о Forum и история шага скрыты, если текущий личный токен, board ACL или ACL темы не подтверждены. Состояние `linked` не доказывает актуальную идентичность сообщения; индикатор соответствия требует текущего чтения. Отзыв рецензента блокирует новые действия, а прошлые подтверждения не уничтожаются. После восстановления доступа проверка выполняется заново; это не автоматический отзыв уже опубликованных публичных материалов.

Перед новым POST Forum (в том числе повтором после однозначного отказа) Engine должен вернуть точную опубликованную редакцию и тот же публичный адрес. Для Lite после публикации требуется повторный `php bin/workspace lite:inspect SITE_ID OWNER_ID`, не старше 15 минут. Проверяется опубликованный SHA всего нативного JSON и точное содержимое страницы. Даже нерелевантное изменение сайта блокирует новое объявление — создайте новый согласованный маршрут вместо обхода проверки. Проверка не гарантирует, что внешнее содержимое не изменится после наблюдения.

### Прерванная отправка

- Engine: существующая сверка по ожидаемой редакции/истории без повторного PATCH. Если доказательства отсутствуют, состояние остаётся неопределённым. Не публикуйте повторно вслепую.
- Lite: `php bin/workspace lite:reconcile JOB_ID` берёт нативный lock. Исходный SHA означает отсутствие наблюдаемого коммита, ожидаемый SHA и проверенная резервная копия — опубликовано, третье состояние или невалидный backup — неопределённо. После однозначного abort обновите каталог и создайте новый маршрут. Восстановление всего сайта остаётся отдельной операцией владельца с offline и проверкой резервной копии. До записи worker повторно проверяет права/рецензентов; отозванная очередь завершается без записи. Сверка результата не повторяет запись даже при отзыве прав автора.
- Forum: при `sending` дождитесь завершения или штатной сверки (60 секунд). При `pending` сверяется заявка. При `uncertain` найдите опубликованную тему в Forum под личной учётной записью, укажите её UUID в карточке и подтвердите MFA. Сверяются раздел, заголовок, первый пост, автор и хеш первоначального payload; неверная тема не привязывается. Нативное действие attach также проверяет эти условия для зарезервированного маршрута. При отсутствии доказательств повторный POST запрещён. Автоматический поиск по всему форуму не выполняется.

Приёмка: `php tests/editorial_capabilities_unit.php`, `php tests/editorial_db.php`, `php tests/lite_db.php` с поддерживаемой нативной установкой, `python3 -B tests/editorial_schema.py`. Выполнить DB-наборы на SQLite и PostgreSQL. На разрешённом тестовом контуре проверить потерю ответа, несовпадение версии, редактирование CMS до нового объявления, отзыв прав рецензента и Forum, восстановление с неверным/верным UUID. Убедиться, что внешние записи не повторились. Схема 50 без новых миграций, старые записи не переписываются.
